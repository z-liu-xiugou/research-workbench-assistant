# 每日仓库检查

用户逐次发起的维护使用 [持续维护与迭代计划](MAINTENANCE_PLAN.md)：默认每轮选一项；用户要求批量维护时，可以处理多项独立任务，分别验证、提交并记录证据。该清单与下述定时健康检查分别管理。

已配置 GitHub Actions 每天 UTC 01:17（北京时间 09:17）运行现有测试、公开文件扫描和分发包验证，覆盖 Windows/Linux、Python 3.10/3.12。分发包检查从本次提交生成 ZIP，在临时目录安装，再验证基础记录和备份恢复；检查范围见 [分发包验证](DISTRIBUTION_VALIDATION.md)。可以在 Actions 的 tests 工作流中手动运行。定时运行可能延迟，长期不活跃的公开仓库可能被 GitHub 停用定时触发。

任务只有仓库读取权限，不自动修改代码、关闭 Issue 或发布版本。失败记录位于 Actions；通知是否发送取决于维护者自己的 GitHub Actions 通知设置。公开文件检查只识别已知模式，不保证识别所有敏感内容。

Actions 的版本更新另由 [Dependabot 配置](DEPENDENCY_UPDATES.md) 每周检查。它可以提出依赖更新 PR，PR 需要通过同一工作流并由维护者审查；未配置自动合并。这与每日只读检查、后台 AI 开发分别管理。
