# OpenAI 开源计划准备路线

## 1. 申请目标

项目应首先成为真实、持续维护的开源科研工具，再以维护者身份申请 Codex for Open Source。不能把“准备开发”写成“已经获得社区使用”。

## 2. 需要积累的公开证据

- 可安装、可运行的公开仓库；
- 清晰的 README、架构、路线图和隐私边界；
- 自动测试和持续集成记录；
- 正式版本和发布说明；
- 外部用户的 Issue、讨论、反馈或贡献；
- 下载量、Star、Fork 或下游使用情况；
- 维护者处理 Issue、审查 PR 和发布版本的持续记录；
- Codex/OpenAI API 用于维护自动化的具体工作流。

官方没有公布必须达到的 Star 或下载量，因此重点是证明项目具有真实使用价值、持续维护责任或明确的科研生态意义。

## 3. 推荐申请叙事

项目解决的是 AI 辅助科研中的长期状态丢失和证据失真问题：它把科研进展、决策、实验、文献和证据保存在本地结构化工作台中，使不同 AI 对话能够可靠续接，并生成可人工阅读和机器检索的知识库。

申请材料应分别回答：

- 谁在使用；
- 解决了什么重复性科研问题；
- 为什么现有聊天记录或普通笔记工具不够；
- 申请人承担哪些维护工作；
- API Credits 将如何用于测试、评估、PR 审查、发布和维护，而不是笼统地写“调用 AI”。

## 4. 不建议立即申请的情况

- 只有规划文档，没有可运行代码；
- 仓库刚创建，没有版本和使用反馈；
- 公开内容仍含个人路径或当前课题材料；
- 项目只是现有私人 Skill 改名，没有通用配置和安装流程；
- 没有持续维护计划。
