# 首次使用验收（约 10 分钟）

状态：已收到外部使用体验建议 [#12](https://github.com/z-liu-xiugou/research-workbench-assistant/issues/12)、[#13](https://github.com/z-liu-xiugou/research-workbench-assistant/issues/13)。两条建议说明本地试用遇到的使用门槛，但未提供本清单各步骤的结果、系统和版本；#9 的完整链路验收仍待补充。自动测试不算外部验收。

请新建一个空的演示项目，所有记录使用虚构内容。

1. 按 [安装指南](GETTING_STARTED.md) 安装，记录 Python 与技能版本。
2. 在 Codex 打开演示项目，输入 `$research-workbench 初始化一个名为虚构课题的工作台`。确认生成工作台目录，已有文件未被覆盖。
3. 输入 `记录一项计划：准备虚构基线实验，状态为计划中`。确认记录有 ID，当前状态与日志中均可找到。
4. 输入 `搜索基线，先给摘要，再查看该记录的完整内容`。确认摘要和完整内容一致。
5. 关闭对话，在同一演示项目新建对话，输入 `$research-workbench 继续上次工作`。确认能找回该计划，不声称实验已完成。
6. 请求将工作台备份到演示项目内的新文件，再恢复到一个不存在的新目录。确认记录 ID、内容和历史保留，原目录未变化。
7. 如失败，停在失败步骤，记录错误；不要删除已有记录后伪装成成功。

已升级到包含本轮改动的主分支时，还可以自愿检查两条建议的第一版：

- 项目偏好：只填写语言和详略，其他留待定；换到另一个虚构项目，不沿用前一个项目的设置。修改偏好后，在新对话确认输出是否采用新值，并检查备份恢复仍保留档案。见 [引导说明](ONBOARDING.md)。
- 本地总览：请求“更新项目总览”，双击 `OVERVIEW.html` 检查中文搜索、任务和候选筛选、原记录入口。新增一条记录后页面仍为旧快照，再更新总览确认显示变化。见 [总览说明](OVERVIEW.md)。

维护者记录反馈时，请将“收到使用建议”“功能已实现”“用户确认体验改善”和“完整链路验收通过”分别登记，不凭功能建议关闭 #9。

在仓库 Issues 选择“试用反馈”。只提交脱敏结果，不上传整份真实工作台、论文或研究数据。维护者应把工具自测与外部试用分别登记；收到实际反馈后才能完成 #9 的外部验收。
