# 开源实施路线图

## 阶段 0：边界与基线

### 任务

- 保存现有助手只读副本和哈希清单；
- 建立 Git 隐私隔离；
- 明确产品范围、数据模型和公开边界；
- 决定项目名称、许可证和首个支持平台。

### 完成标准

- Git 状态中不出现 `_private_reference/`；
- 公开文件中没有个人路径、密钥、论文全文或未公开研究内容；
- v0.1 范围和不做事项得到用户确认。

## 阶段 1：v0.1 科研记忆核心

### 任务

- 创建可安装的 Python 包和命令行入口；
- 实现项目初始化和配置读取；
- 实现事件、事实、任务、决策、问题和成果 Schema；
- 从结构化记录生成工作台 Markdown；
- 实现轻量续接和完整审计路由；
- 实现路径、证据和状态一致性检查。

### 完成标准

- 在一个空目录中初始化示例科研项目；
- 完成一次任务后能够生成工作日志和当前状态；
- 新对话只读取断点和相关记录即可恢复任务；
- 删除生成的 Markdown 后可以从结构化记录重建；
- Windows 和 Linux 自动测试通过。

## 阶段 2：v0.2 文献笔记库

### 任务

- 迁移 PDF 校验、正文提取和哈希去重；
- 定义通用论文笔记 Schema；
- 支持 Markdown/JSON 双输出；
- 支持 quick/deep、修订链和人工确认状态；
- 提供可公开的测试论文或合成夹具。

### 完成标准

- 同一论文不会生成两个当前版本；
- Markdown 与 JSON 的题名、结论和证据一致；
- 失败不会留下半写文件；
- 不依赖当前主配协同目录或字段。

## 阶段 3：v0.3 文献发现与记忆网络

### 任务

- 建立可替换的文献检索适配器；
- 合并 DOI、arXiv ID 和规范化题名进行去重；
- 区分候选、已获取、已笔记和人工已读；
- 建立节点、关系和语义索引；
- 提供增量检索和检索日志。

### 完成标准

- 搜索结果保留来源和检索时间；
- 无全文时不能生成全文级结论；
- 关系可以追溯到论文页码、章节或项目证据；
- 不绕过版权、登录或访问控制。

## 阶段 4：v0.4 社区发布

### 任务

- 将独立工作流拆成多个 Skill；
- 将多个 Skill 和可选连接器打包为插件；
- 提供安装、升级、迁移和卸载说明；
- 建立 CI、Issue 模板、贡献规范、安全说明和版本发布流程；
- 邀请真实研究生试用并收集问题。

### 完成标准

- 新用户能够仅按 README 完成安装和第一个项目；
- 至少形成可复现演示和真实外部反馈；
- 公开仓库持续维护，而不是一次性上传。

## 阶段 5：OpenAI 开源计划申请

- 汇总实际使用量、版本、Issue、PR 和维护记录；
- 展示 Codex 如何用于代码审查、测试、发布和维护自动化；
- 说明项目解决的科研社区问题；
- 只陈述可以由公开仓库验证的数据。
