# 社区首发文案

## 可直接复制的短帖

我开源了一个面向研究生的 Codex 科研工作台助手。

起点很简单：用 AI 做研究时，每次换对话都要重新交代目标和进度，聊过的方案、试过的实验和读过的文献容易散落在历史记录里。我希望把这些内容留在项目本地，下一次能接着做。

目前的早期版本可以初始化工作台，记录进展、问题和下一步，保留修订历史，并把提供的文献笔记保存成 Markdown 和 JSON。新开 Codex 对话后，可以从保存的断点继续，不必默认扫描整个项目。

现在还没有自带自动搜论文、PDF 解析或知识图谱；这些是后续方向。欢迎先试用最基本的“记录—续接”流程，告诉我哪些信息最容易丢、哪些操作太麻烦。

项目：https://github.com/z-liu-xiugou/research-workbench-assistant

README 有安装命令，Python 3.10+，无额外 Python 依赖。请用虚构或脱敏材料反馈，不要公开未发表数据。

## 演示顺序（约一分钟）

1. 展示安装命令和 Codex 中的 $research-workbench。
2. 用虚构项目初始化。
3. 写入一条进展和下一步，展示 ACTIVE_CONTEXT.md。
4. 新开对话，从断点继续，展示能恢复哪些信息。
5. 展示同一条虚构文献笔记的 Markdown 与 JSON。

录屏前检查用户名、路径、账号、未发表材料是否入镜。不要说“永不失忆”“自动完成科研”或“已经完成全部文献管理”。

## 维护节奏建议

每周集中整理反馈，优先处理数据丢失和安装失败，再改续接体验；发布时提供变更说明与测试结果。先收集少量真实试用反馈，不用 Star 数代替可用性验证。长期维护尚未自动化，也不代表维护者承诺固定响应时限。
